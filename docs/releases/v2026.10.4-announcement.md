# AIWG 2026.10.4 - Inspectable rules and decision-offload visibility

AIWG 2026.10.4 makes it easier to inspect the rules that apply to a workspace,
see whether bounded decision offload is configured and being used, and preserve
that guidance as provider context is regenerated or compacted. It also adds
release-candidate evidence and promotion infrastructure, improves deployment
performance, and reduces session-import memory use.

## Inspect the rules for your workspace

The scoped rule inventory lists provenance, activation, and fetch paths. You can
filter by capability or provider and export complete rule bodies. The inventory
separates available catalog rules from applicable rules; recorded deployment does
not prove that a running provider session loaded a rule.

Try asking: “List the active rules for this workspace and show their full bodies.”
See the [CLI reference](https://github.com/jmagly/aiwg/blob/v2026.10.4/docs/cli-reference.md)
for command details.

## See decision-offload readiness and adoption

Status, doctor, and steward expose offline readiness, recorded opportunities,
answered calls, fallbacks, and unknown recording states. Diagnostic calls remain
separate from ordinary adoption. Compact guidance survives regeneration and
compaction when the addon and ask configuration are enabled.

Offload remains advisory. A missing or disabled service falls back to a local
decision, and a recorded rule deployment is not a guarantee that every provider
will follow it. See the [observability guide](https://github.com/jmagly/aiwg/blob/v2026.10.4/docs/decision/offload-observability.md).

## Validate candidates before publication

Release infrastructure retains candidate packages and validates source and
artifact identity before promotion. Quarterly comparison evidence is reused
within its allowed quarter; routine releases do not repeat the full provider
comparison. Production promotion requires configured identities and valid retained
evidence. Public npm publication runs through GitHub Actions.

## Upgrade

Update your installed AIWG package using your existing installation method, then
refresh the frameworks and addons deployed to your workspace. Review custom rule
pins and provider context after refreshing. See the
[changelog](https://github.com/jmagly/aiwg/blob/v2026.10.4/CHANGELOG.md#2026104---2026-10-21)
for the release changes and the
[versioning guide](https://github.com/jmagly/aiwg/blob/v2026.10.4/docs/contributing/versioning.md)
for release publication details.
