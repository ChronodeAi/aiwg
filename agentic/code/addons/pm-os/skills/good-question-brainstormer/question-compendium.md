# Question Compendium

This compendium turns George's notes on questioning into reusable operating material for brainstorming better questions.

## Core Principles

### A beautiful question is ambitious yet actionable

The question should be large enough to change perception, but concrete enough to produce action. If it cannot lead to observation, experiment, conversation, prototype, or decision, it is probably too abstract.

Useful test: "What could we do differently next week if this question mattered?"

### Questions organize attention around what is not known

Answers close loops. Questions open search spaces. A strong question creates a place in the mind where new information can land.

Use questions when:

- The current answer feels stale.
- Expertise is creating tunnel vision.
- The team is repeating the same debate.
- There is conflicting data, no data, or only anecdata.
- A decision will cascade into many future decisions.

### Questioning plus action equals innovation

Questioning without action becomes philosophy. Action without questioning becomes local optimization.

The skill should always move from inquiry to some form of action:

- Observe a real user.
- Run a small experiment.
- Sketch a prototype.
- Ask a collaborator.
- Define a decision principle.
- Change one behavior for a week.

### Do not answer too quickly

The worst move with a difficult question is often to answer it immediately. Stay with the question long enough for non-obvious variants to appear.

Practical move: generate the easy questions first to lower anxiety, then push into deeper or stranger versions.

### Beginners often ask better questions than experts

Expertise narrows possibility. Beginner's mind reopens it.

Use this prompt: "How would a smart seven-year-old, a new hire, or a user with no context describe what is strange here?"

### Context beats abstraction

Contextual inquiry means asking close to the real situation: observe, listen, and notice what people do before deciding what the correct question is.

Useful prompt: "What would I need to watch in the real world before trusting my current question?"

### Eigenquestions reveal latent principles

An eigenquestion is not just a better prompt. It is the deeper question that uncovers a durable principle.

Use it when:

- A debate keeps recurring.
- A decision will set precedent.
- There is no clean data.
- The org is forming a new habit, ritual, or operating principle.
- A one-off answer would create confusion later.

Template: "What principle should decide this class of decisions?"

## Question Lanes

### Why Questions

Why questions penetrate assumptions, causes, beneficiaries, and constraints.

Use when the problem frame feels inherited, shallow, or overconfident.

Examples:

- Why does this situation exist?
- Why is this a problem, for whom, and now?
- Why has nobody solved this before?
- Why do we personally want to invest time here?
- Why do we do it this way?
- Why does the status quo benefit from remaining unchanged?
- Why are we treating an individual behavior as a systemic failure, or vice versa?
- Why would the obvious answer be wrong?
- Why are we afraid to ask this question directly?
- Why would a new entrant see this differently?

### What If Questions

What-if questions expand possibility space. They work through reversal, abundance, scarcity, removal, and recombination.

Use when the current answer space is too cramped.

Examples:

- What if money were no object?
- What if we had to charge one tenth as much?
- What if we had to make this work with one tenth the time?
- What if the company, product, or process did not exist?
- What if a startup were trying to disrupt us?
- What if we could not use our current channel, feature, meeting, or process?
- What if we tried the opposite of the current strategy?
- What if this were a cause, not just a business?
- What if the constraint is the clue?
- What if the goal is right but the unit of analysis is wrong?

### How Questions

How questions convert inquiry into action. They should follow Why and What if, not replace them too early.

Use when enough exploration has happened and the work needs a testable next step.

Examples:

- How can we make a better experiment?
- How will we know what we learned?
- How can we build a petri dish that tests this without risking the whole system?
- How could we sketch this as a question embodied in a prototype?
- How can we fail differently next time?
- How can we involve people with different tools so they get stuck in different places?
- How can we turn this question into one observation, one conversation, or one prototype?
- How can we make the smallest change that would teach us something?
- How could we ask this question without making people defensive?
- How can we keep questioning without drifting into inaction?

### Eigenquestions

Eigenquestions uncover reusable decision principles.

Use when the situation points beyond itself.

Examples:

- What principle would make this decision easier the next ten times?
- What recurring debate is this really a version of?
- What would we decide here if we were designing the operating system, not resolving the ticket?
- What tradeoff are we implicitly making but refusing to name?
- What class of decisions will this answer influence?
- What is the smallest principle that explains our preferred answer?
- When should we optimize for speed, quality, learning, trust, or optionality?
- What would make this a durable rule rather than a local preference?
- What is the question beneath the question?
- What future confusion are we creating if we answer this as a one-off?

### Contextual Inquiry Questions

Contextual inquiry brings questioning into the real world.

Use when the team is theorizing too much.

Examples:

- What would we need to observe before believing our current story?
- Where does this problem happen in real life?
- What is the user doing immediately before and after this moment?
- What are people working around?
- What do they say they do, and what do they actually do?
- What would surprise us if we watched for an hour?
- What are we missing because we are asking from a conference room?
- Who experiences the cost but lacks the authority to fix it?
- What context changes the meaning of the behavior?
- What question would the user's environment ask for us?

### Appreciative Inquiry Questions

Appreciative inquiry starts from what is already alive, effective, or energizing.

Use when the problem frame is too negative or demotivating.

Examples:

- What has worked here before?
- When did this feel easy, alive, or effective?
- What conditions made that possible?
- Who is already solving this in miniature?
- What do users already value enough to fight for?
- What part of the current system should not be disturbed?
- What strength are we underusing?
- What small success could we amplify?
- What would make us hopeful enough to act?
- What one small change could bring the good pattern back?

### Story and Life Questions

Story questions evaluate direction, identity, and meaning.

Use for career, life planning, writing, founder ideas, or decisions where pure utility misses the point.

Examples:

- What path leads to a better story?
- How do I make this stranger or more interesting?
- Looking back, what do I want to say I accomplished?
- Why am I climbing this mountain?
- What is waiting at the top?
- Am I enjoying the climb itself?
- What am I leaving behind?
- What would I do if I could not fail?
- What if I do nothing?
- What would a confident person do next?

## Product and Strategy Question Bank

### Product Strategy

- If our product vanished tomorrow, who would miss it and why?
- What core human need would go unmet?
- What business are we really in as the world and customer lives change?
- Who are we at our core, and who were we when we were at our best?
- What should we stop doing?
- What do we stand for, and what do we stand against?
- What would a new CEO do if we were kicked out of our own company?
- What would a startup challenge about our assumptions?
- What would make this product a cause, not just a tool?
- Which assumption in our strategy is least examined and most load-bearing?

### Product Discovery

- What do we need to learn before choosing a solution?
- What are we pretending to know?
- What user behavior would change our mind?
- Which customer has the sharpest version of this problem?
- What workaround proves the pain already exists?
- What are users hiring the current solution to do?
- What emotional, social, and functional jobs are tangled together?
- What would make a user switch now rather than someday?
- What is the smallest signal that the problem is real?
- What would we ask if we were forbidden from pitching a solution?

### Innovation

- What hidden constraint might be turned into the idea?
- What distant field has already solved an analogous problem?
- What combination seems wrong but might unlock the space?
- What would we try if we had to embarrass the current category?
- What would a musician, engineer, child, and operator each ask?
- What dissonant feedback are we dismissing too quickly?
- What went right in this failure?
- What went wrong in this success?
- Are we failing differently each time?
- Who might find this question interesting enough to join?

### Leadership and Organizations

- What questions are people not allowed to ask here?
- What would it cost leadership to genuinely allow this question?
- Where are answers being used to preserve control?
- What dumb question would Peter Drucker ask?
- Which question would make the strategy obvious if we could answer it?
- What is the chaos, and what point of view needs to be provided?
- What recurring meeting exists because we lack a better question?
- What would a flatter, more networked version of this system ask?
- What question would transfer ownership instead of assigning blame?
- How involved does the question-asker want to be in the solution?

### Stuck Decisions

- What would need to be true for each option to be right?
- Which choice creates the most useful information?
- Which choice preserves optionality?
- Which choice compounds into better future choices?
- What am I optimizing for without admitting it?
- What decision principle would prevent this from becoming a recurring debate?
- What do I fear learning if I test this?
- What one-week experiment would reduce the uncertainty most?
- Which path would still feel alive if it failed?
- What is the cost of doing nothing?

## Question Improvement Moves

### Open a Closed Question

Closed: "Should we launch this?"

Open: "What would need to be true for launching now to be the right move?"

### Close a Broad Question

Broad: "How do we grow?"

Sharper: "Which segment would miss us most if the product disappeared tomorrow?"

### Add a System Lens

Individual blame: "Why are users not doing this?"

System lens: "What in the context makes this behavior unlikely?"

### Add Ownership

Complaint: "Why does nobody care?"

Owned question: "What would I be willing to do if I believed this mattered?"

### Add Action

Abstract: "Why is this hard?"

Actionable: "What small observation would teach us why this is hard?"

### Add Reversal

Default: "How do we add value?"

Reverse: "What value are we destroying without noticing?"

### Add Time

Static: "What should we do?"

Temporal: "What would still matter one year from now?"

## Ranking Rubric

Score each candidate question from 1-5 on:

- Leverage: Could this change many downstream decisions?
- Novelty: Does it escape the obvious frame?
- Actionability: Could it produce a test, observation, or decision?
- Specificity: Is it concrete enough to answer?
- Generativity: Could it produce several layers of answers?
- Charge: Does it make people pay attention without becoming melodramatic?

The best first question is not always the highest total. Prefer the question that opens the next useful door.

## Anti-Patterns

- Answering too early.
- Asking questions so broad they cannot create action.
- Asking questions so narrow they only validate the current plan.
- Generating five safe questions and calling it a brainstorm.
- Confusing questioning with complaining.
- Staying in inquiry after the next experiment is obvious.
- Using questions to avoid taking a position.
- Treating expertise as permission to stop noticing.
- Asking performative questions that no one has power to act on.
- Ranking questions by cleverness rather than leverage.
