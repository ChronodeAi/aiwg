# Examples

Real product documents showing what strong PM writing looks like. Use these to calibrate the quality of your own thinking — not the format, but the substance: how problems are evidenced, how outcomes are made specific and measurable, how language earns trust rather than hedging.

---

## Example PRDs

Read these before drafting. The goal is not to copy the structure, but to internalise the standard: what level of specificity, what quality of evidence, what clarity of language separates a PRD that gets built from one that gets questioned.

| File | Context | What makes it strong |
|------|---------|----------------------|
| `Shift Swap Project Charter.md` | Workforce scheduling — SMS-based shift broadcasting MVP | Problem statement tied directly to a measurable behaviour; stakeholder roles defined with precision; success metrics that track the thing that actually matters |
| `Shopify to Quickbooks Connector Product Requirements.md` | B2B integration — financial data sync between two platforms | API-level specificity in requirements; user stories grounded in real workflows; success metrics framed as countable outcomes, not abstract goals |

---

## How to Use These Examples

**Before drafting:** Read the example closest to your context. Notice how the problem is framed — is it a behaviour to change, a cost to eliminate, a job to make easier? Notice how evidence appears — not as assertions but as grounded observations. Notice how success metrics name the specific thing that will move, not a proxy.

**As a calibration question during drafting:** Ask "would someone reading this know exactly what we're building and why it matters?" If not, these examples show what that looks like when it's done.

**When the AI is reviewing your PRD:** Run `/review` after drafting. Reference these examples during the UX Research or Devil's Advocate steps as a quality benchmark — what does strong evidence look like compared to what's in the document?

**When the AI asks for context:** You can paste a section from an example and say "this is the quality level I'm aiming for" — the AI will match it.

## Adding Examples

To add a new example:
1. Save the file in this folder with a descriptive name
2. Add a row to the table above with a "What makes it strong" description
3. Update `knowledge/INDEX.md` to include the new example

Examples ship with pm-os and are updated on version upgrades. Do not use this folder for your own Work output — save that to `📂 Context/Work/PRDs/` instead.
