# Systemico Model

Use When: B2B, Building a New Product, Sequence Work
Author: Barry O’Reilly
Don't Use When: Internal Product, Mid/Low Influence, Need Quick Decisions
Best for Prioritising...: Features, Initiatives/Epics
Artefact: Agnostic
Advantages: Lightweight, Not Dogmatic
Limitations: Draw The Rest Of The Owl🦉, Requires Your Goals First, Won't Help Set Goals
Read Case Study: https://barryoreilly.com/explore/blog/the-systemico-model/

# Description

The Systemico Model and user goal/engagement components are meant to help the team and product manager create value by giving them a visual framework that lets them add more dimensions to value propositions. 

The goal is for the team to be able to use their development process to get the most value out of it while cutting down on waste and over-engineered solutions that don't meet user needs.

The model consists of four layers: core value proposition, core product experience, supporting product experience and delighters. Each layer represents a different level of user expectation and satisfaction. The core value proposition is what the user needs or wants from the product. The core product experience is how the product delivers on that need or want. The supporting product experience is how the product enhances or facilitates the core experience. The delighters are unexpected or surprising elements that make the user happy.
