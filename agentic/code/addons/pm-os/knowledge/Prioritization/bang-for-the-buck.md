# Bang For The Buck

Use When: Limited Influence, Need Quick Decisions, Prioritise Opportunities
Author: Scott Sehlhorst
Don't Use When: Vision Setting/Long-Term Roadmapping
Best for Prioritising...: Features, Initiatives/Epics
Artefact: Agnostic
Advantages: Lightweight
Limitations: Won't Help Set Goals
Read Case Study: https://tynerblain.com/blog/2008/10/20/planning-sprints-part-2/

# Description

It is a way of choosing which features or items to work on in a sprint based on their value and cost.

Value is how much benefit the feature will deliver to the customers or users. Cost is how much effort or time it will take to deliver the feature. The article suggests using a simple formula to calculate the Bang for the Buck of each feature: Value / Cost.

The features with the highest Bang for the Buck are those that have high value and low cost. These are the features that should be done first in a sprint. The features with the lowest Bang for the Buck are those that have low value and high cost. These are the features that should be done last or not at all. You create a 2x2 plot and work through the options clockwise.
