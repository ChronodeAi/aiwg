## Frameworks/ (118 files across 4 stages)

Organized by PM lifecycle stage. Each framework includes metadata on actionability, risk focus, and type, plus a link to a case study or source.

### discovery/
Frameworks for discovering what to build. Includes: `opportunity-solution-tree`, `jobs-to-be-done`, `user-story-mapping`, `lean-canvas`, `design-sprint`, etc.

### validation/
Frameworks for validating what we're building. Includes: `a-b-test`, `usability-test`, `wizard-of-oz`, `concierge`, `fake-door-testing`, etc.

### build/
Frameworks for building and delivering. Includes: `scrum`, `kanban`, `shape-up`, `story-mapping`, `rice`, etc.

### grow/
Frameworks for growing and scaling. Includes: `north-star-metric`, `growth-loops`, `aarrr`, `heart`, etc.

## Writing-Styles/ (4 guides)

Practical writing guides for tailoring PM output to different audiences. Use when drafting any communication artifact — PRDs, status updates, stakeholder messages, help docs.

| File | Audience | Tone | Use For |
|------|----------|------|---------|
| `writing-style-customer.md` | Customers and prospects | Friendly, clear, benefit-led | Product marketing, help docs, email, in-app messaging |
| `writing-style-executive.md` | Executives, board, investors | Strategic, concise, data-driven | Board updates, QBRs, strategy docs, investment proposals |
| `writing-style-internal.md` | Team and colleagues | Direct, collaborative, casual | PRDs, Slack updates, team email, meeting notes |
| `writing-style-technical.md` | Engineers, developers | Precise, detailed, unambiguous | Engineering PRDs, API docs, architecture decisions, release notes |

Each file includes: characteristics, rules with good/bad examples, sample templates for common content types, and "When to Use" guidance.

## How to Navigate This Index

1. **User asks about interviews?** → Go to Interview-Questions/ section
2. **User needs to prioritize?** → Go to Prioritization/ section, use tag reference to filter
3. **User wants metric examples?** → Go to Metrics/ section, find by company or category
4. **User needs a framework?** → Go to Frameworks/ section, pick by lifecycle stage
5. **User wants to practice PM skills?** → Go to PM Tasks/ section, pick by theme
6. **User wants to read articles?** → Go to Resources/ section, pick by topic
7. **User asks about a specific company's metrics?** → Go to Metrics/ Quick Lookup
8. **User asks how to write for a specific audience?** → Go to Writing-Styles/ section
9. **User wants to see example PRD output or calibrate content quality?** → Go to `examples/` (root level, not inside knowledge/) — read `examples/README.md` first for context and descriptions
